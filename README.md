# Транслятор Stable → Java

Учебный проект: программа на языке **Stable** проверяется и переводится в самостоятельный файл `.java`. Затем этот файл можно собрать обычным `javac` и запустить на JVM. Актуальные правила языка описаны в [спецификации Stable 0.6](<openspec/context/specification_language/Спецификация Stable 0.6.md>). Код транслятора разделён на лексер, парсер, дерево программы (AST), семантический анализатор и генератор Java. Он не является однопроходным.

Проверка по спецификации 0.6 описана в [отчёте V2](STABLE_0_6_COMPLIANCE_REPORT_V2.md). Основные тесты проходят, но **полное соответствие пока не заявляется**: на проверенной Windows/JDK обнаружена потеря символов, отсутствующих в системной кодировке вывода, при `print(input<neigh>())`. Подробнее — в разделе D-1 отчёта.

## Что понадобится

- JDK с командами `java` и `javac` в `PATH` (`java -version`, `javac -version`). В коде используются возможности Java 17; описанные ниже проверки фактически выполнены на JDK 25.0.1. Совместимость с JDK 17 отдельно не подтверждена.
- PowerShell для готовых скриптов. Команды ниже приведены для запуска из корня проекта на Windows.

Сторонние библиотеки и менеджер зависимостей для сборки не нужны.

## Быстрый запуск

```powershell
.\scripts\run-stable.ps1 examples\hello.stable
```

Когда программа запросит ввод, напишите `Storm` и нажмите Enter. Результат: `Hello, Storm`. Скрипт последовательно собирает транслятор, переводит `.stable` в Java, компилирует полученный файл и запускает его. Он перемещает сгенерированный исходник в `out/generated-sources/ZherebtsovHello.java`, а классы программы сохраняет в `out/generated-classes/`.

Чтобы увидеть отдельные этапы, выполните их вручную:

```powershell
.\scripts\build.ps1
java -cp out/classes stable.compiler.Main examples\hello.stable
New-Item -ItemType Directory -Force out/generated-classes | Out-Null
javac -encoding UTF-8 -d out/generated-classes examples\ZherebtsovHello.java
java -cp out/generated-classes ZherebtsovHello
```

При ручном вызове `Main` Java-файл создаётся **рядом с исходным** `.stable` и путь к нему печатается в консоль. Сам транслятор `javac` не вызывает. Имя публичного Java-класса выводится из имени исходного файла: `hello.stable` → `ZherebtsovHello.java`; недопустимые для имени символы кодируются как `_uXXXX_` (`some-name.stable` → `ZherebtsovSome_u002D_Name.java`).

## Как устроен перевод

```text
исходник .stable (UTF-8)
  → Lexer: последовательность токенов с позициями
  → Parser: AST — дерево выражений, операторов и функций
  → Semantic: проверка имён, областей видимости и типов
  → Emitter: текст самостоятельного Java-класса
  → javac и JVM: отдельные этапы после трансляции
```

| Файл | За что отвечает |
|---|---|
| [`Main.java`](src/stable/compiler/Main.java), [`Translator.java`](src/stable/compiler/Translator.java) | Командная строка и последовательность этапов. `Translator` записывает готовый Java-файл через временный файл, поэтому ошибка проверки не заменяет старый результат. |
| [`Lexer.java`](src/stable/compiler/Lexer.java), [`Language.java`](src/stable/compiler/Language.java) | Лексемы, комментарии `//`, литералы, позиции в исходнике и представление типов. |
| [`Parser.java`](src/stable/compiler/Parser.java), [`Ast.java`](src/stable/compiler/Ast.java) | Разбор структуры программы и приоритетов операций; AST сохраняет смысловую форму программы, ещё без проверки допустимости типов. |
| [`Semantic.java`](src/stable/compiler/Semantic.java) | Разрешение переменных и функций, области видимости, типы выражений, аргументы и обязательный `return`; сопоставление Stable-имён с безопасными Java-именами. |
| [`Emitter.java`](src/stable/compiler/Emitter.java) | Генерация Java-кода из проверенного AST, а также служебных методов для `input<T>()` и правил времени выполнения. |
| [`Constants.java`](src/stable/compiler/constants/Constants.java), [`Diagnostic.java`](src/stable/compiler/Diagnostic.java) | Общие обозначения языка и ошибки с категорией, строкой и столбцом. |

Например, для `print(2 + 3 * 4);` лексер распознаёт слова, числа и знаки; парсер строит дерево, в котором умножение находится внутри правой части сложения; анализатор устанавливает тип `hoof`; генератор печатает эквивалентное Java-выражение. Такой порядок позволяет отделить ошибку записи программы от ошибки типов.

## Минимальный пример Stable

```stable
zherebtsov Demo {
    function hoof doubleValue(hoof value) {
        return value * 2;
    }

    run {
        hoof result = doubleValue(3);
        print(result);
    }
}
```

Выполнение начинается с единственного блока `run`; функции объявляются перед ним. Простые типы: `hoof` (целое), `stride` (вещественное), `neigh` (строка), `tamed` (значения `tame` и `wild`). Массивы записываются как `herd<T>`, например `herd<hoof> values = [1, 2];`. `input<T>()` читает одну строку, `print(...)` выводит простое значение и перевод строки. Полные правила допустимых выражений, операций и ошибок находятся в спецификации 0.6.

При лексической, синтаксической или семантической ошибке `Main` выводит категорию, строку, столбец и причину, завершает работу с ненулевым кодом и не создаёт новый Java-файл. Ошибки времени выполнения возникают уже после успешной трансляции и компиляции Java-программы.

## Как проверить проект

```powershell
.\scripts\test.ps1                         # Java-тесты и исходный набор примеров
.\scripts\test.ps1 -SkipFixtures            # Только Java-тесты
.\scripts\test-fixtures.ps1                  # Только examples/stable_tests
.\audit\stable06-cases.ps1                   # Адресные проверки Stable 0.6
.\audit\stable06-v2-cases.ps1                # Матрица восьми типов и дополнительные случаи
.\audit\stable06-v2-observations.ps1         # Наблюдения о вводе/выводе и runtime-поведении
```

Java-тесты лежат в [`src/stable/compiler/tests`](src/stable/compiler/tests). Примеры в [`examples/stable_tests`](examples/stable_tests) разделены на корректные программы, программы с ошибками, входные данные и ожидаемый вывод. Положительный тест проверяет **всю цепочку**: перевод → `javac` → запуск → сравнение вывода. Отрицательный тест проверяет категорию ошибки и отсутствие успешного выходного файла. Скрипты аудита создают изолированные копии программ в `out/`; этот каталог игнорируется Git.

## Как использовать проект как основу для своего языка

1. **Опишите язык прежде, чем менять код:** алфавит, грамматику, типы, области видимости, приоритеты операций и правила запуска. Для Stable таким контрактом служит спецификация 0.6.
2. **Определите токены:** ключевые слова и знаки в `Constants`, правила распознавания в `Lexer`. Лексер должен сообщать позицию ошибки и не решать вопросы типов.
3. **Опишите дерево программы:** виды узлов в `Ast`, а затем правила построения узлов в `Parser`. Для новых операций отдельно задайте приоритет и ассоциативность.
4. **Добавьте смысловые проверки в `Semantic`:** где объявлено имя, какой у выражения тип, какие преобразования допустимы, можно ли присваивать цели. Здесь же подготовьте информацию, нужную генератору.
5. **Переведите проверенное дерево в Java в `Emitter`:** сопоставьте типы и конструкции, продумайте различия поведения Stable и Java (например, вывод `tame`/`wild`, ввод и деление на ноль).
6. **Добавьте парные тесты:** корректная программа должна собраться и выдать заранее определённый результат; некорректная — остановиться на нужной стадии. Для каждого нового правила полезно проверить границы и взаимодействие с уже существующими правилами.

Изменение одного синтаксического правила часто затрагивает несколько этапов. Например, добавление оператора потребует обновить распознавание знака в `Lexer`, разбор приоритета в `Parser`, проверку типов в `Semantic`, генерацию в `Emitter` и положительные/отрицательные тесты. Комментарии в Java-коде и PowerShell-скриптах поясняют текущие решения рядом с реализацией.
