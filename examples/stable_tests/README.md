# Набор тестов Stable 0.4

Эти примеры составлены по спецификации Stable 0.4 для проверки компилятора Stable → Java. Ожидаемые результаты выведены из спецификации.

## Что проверяем

| Файл в `valid/` | Конструкции | Ожидаемый вывод |
|---|---|---|
| `basics.stable` | Четыре простых типа, присваивание, арифметика, `%`, целочисленное деление, строки, булевы литералы | `expected/basics.txt` |
| `conditions.stable` | `if/else`, сравнения, `!`, `&&`, `||`, строковое равенство | `expected/conditions.txt` |
| `loops.stable` | `while`, `for`, вложенные циклы, включённая верхняя граница, обратной итерации нет | `expected/loops.txt` |
| `arrays.stable` | `herd<T>`, индексация, изменение элемента, ссылочное присваивание, передача в функцию | `expected/arrays.txt` |
| `functions.stable` | Объявления и вызовы функций, рекурсия, аргументы, все четыре типа возвращаемого значения, вызов как оператор | `expected/functions.txt` |
| `short_circuit.stable` | Ленивые `&&` и `||` на вводе (должна потребоваться только одна строка) | `expected/short_circuit.txt` |
| `inputs.stable` | Ввод `neigh`, отрицательного `hoof`, `stride`, `tamed` | `expected/inputs.txt` |
| `comments_strings.stable` | Комментарии и `//` внутри строки | `expected/comments_strings.txt` |
| `shadowing.stable` | Перекрытие локальной переменной во вложенном блоке | `expected/shadowing.txt` |

Пути `input/*.txt` соответствуют тестам, ожидающим стандартный ввод.

### Ожидаемые отклонения

| Файл в `invalid/` | Ожидаемая категория |
|---|---|
| `type_mismatch.stable` | Семантическая: `hoof` ← `neigh` |
| `string_multiply.stable` | Синтаксическая или типовая (зависит от организации парсера): умножение строк запрещено |
| `mixed_numbers.stable` | Синтаксическая или типовая: `hoof` и `stride` без преобразования |
| `bad_condition.stable` | Семантическая: условие `if` не `tamed` |
| `bad_index.stable` | Семантическая: индекс не `hoof` |
| `for_assign.stable` | Семантическая: изменение переменной `for` |
| `unknown_variable.stable` | Семантическая: необъявленное имя |
| `bad_return.stable` | Семантическая: тип `return` |
| `syntax_missing_semicolon.stable` | Синтаксическая: нет `;` |
| `lexical_invalid_char.stable` | Лексическая: `@` не входит в алфавит кода |
| `invalid_input_type.stable` | Синтаксическая: `input` принимает только простой тип |
| `function_args.stable` | Семантическая: не совпадает число аргументов |

**Особенность:** `runtime_out_of_bounds.stable` и `runtime_division_zero.stable` находятся в `invalid/` по смыслу, но должны *успешно транслироваться* и завершаться ошибкой **во время запуска Java-программы**. Нельзя считать их ошибками парсера или типизации.

## Запуск из корня проекта, PowerShell

Из корня проекта запустите полный набор проверок:

```powershell
.\scripts\test-fixtures.ps1
```

Скрипт транслирует копии программ в папку `out/`, компилирует Java, сравнивает вывод с `expected/`, проверяет категории ошибок и сохранность выходного файла, а также ошибки при запуске. Исходные файлы тестов остаются на месте.

Для ручного запуска программы с вводом (`inputs.stable`):

```powershell
& .\scripts\build.ps1
java -cp out/classes stable.compiler.Main examples\stable_tests\valid\inputs.stable
New-Item -ItemType Directory -Force out/generated | Out-Null
javac -d out/generated examples\stable_tests\valid\ZherebtsovInputs.java
Get-Content examples\stable_tests\input\inputs.txt | java -cp out/generated ZherebtsovInputs
```

**Важно:** имя выходного Java-класса зависит от реализации правила именования файлов. Чтобы не гадать, используйте имя файла, которое транслятор действительно вывел; для имён с `_` по описанному правилу используется кодирование `_uXXXX_`. Для запуска в примере выбраны файлы без подчёркиваний.

## Как оценить агента

- Успешная трансляция валидных программ — лишь первый этап. После неё проверяйте компиляцию `javac` и точное совпадение стандартного вывода с `expected/*.txt`.
- Для ошибочных программ проверяйте ненулевой код завершения, категорию и место ошибки; существующий `.java`-файл не должен заменяться.
- Не исправляйте тесты ради прохождения реализации, пока не сверили спорный случай со спецификацией.
- `shadowing.stable` — **особенно важный тест**: Stable разрешает перекрытие локальных переменных во вложенном блоке, а Java обычно запрещает объявление локальной переменной с тем же именем во вложенной локальной области. Генератор Java должен обеспечить эквивалентную семантику (например, переименованием символов), иначе сгенерированный код не соберётся.
- `string_multiply.stable` может быть отклонён уже синтаксическим парсером версии 0.4. Это допустимо, если правила типизированных выражений действительно реализованы.
